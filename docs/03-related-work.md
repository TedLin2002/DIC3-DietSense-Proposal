## 2.1 AI Technology（AI 技術）

### 2.1.1 影像式食物辨識與營養估計

早期研究以影像分類為主。Food-101 建立了 101 類、101,000 張影像的基準資料集 [A14]；ChineseFoodNet 擴展到 208 類、18.5 萬張中式料理影像 [A16]；針對臺灣，Liu 等人以 EfficientDet 辨識 87 種臺灣料理，mAP 達 0.92 [A17]。Nutrition5k 更進一步收集約 5,000 份餐點的深度影像與成分重量，把問題從「辨識」推向「營養估計」[A15]。

**限制**：影像看不到油量、湯底與隱藏食材，份量也只能從 2D 影像推測。即使是 2025 年的多模態 LLM，從影像估計熱量的 MAPE 仍約 36%（GPT-4o 35.8%、Gemini 64–110%）[A1]。

### 2.1.2 LLM 直接估計營養

ChatGPT 出現後，研究開始評估 LLM 直接回答營養問題的能力。Haman 等人發現 ChatGPT 有 97% 的熱量值落在 USDA ±40% 範圍內 [A3]——但 ±40% 對體重管理而言太寬。與本研究最相關的是臺北醫學大學 Hoang 等人以**臺灣 FDA 食品資料庫**為參考的研究：222 項食物中，GPT-4 熱量僅 39–47% 落在 ±10% 內、58–61% 落在 ±20% 內，且繁中與英文輸入的結果不同 [A2]。NutriBench 建立 11,857 筆餐點描述的基準，測試 12 個 LLM，發現 LLM 準確度接近營養師但快得多，並測試了 RAG 與 CoT 等提示策略 [A8]。Carrillo-Larco 則顯示，對 24 小時飲食回憶文字做參數高效微調後，熱量 MAE 可從 652 kcal 降至 171–191 kcal [A9]。

**限制**：LLM 直接估計的數值不可重現、沒有來源，且 LLM 自述的信心普遍過度自信 [A11]；臨床情境中的幻覺率可達 50–82% [A5]。

### 2.1.3 Tool-use Agent 與檢索增強生成

ReAct 讓 LLM 交錯進行推理與工具行動，在知識密集任務上比純 CoT 更少幻覺 [A6]；Toolformer 讓模型自學呼叫 API [A7]；RAG 讓生成內容能以外部文件為依據 [A20]。飲食領域也開始採用：FoodBase 提供食物命名實體辨識（NER）語料 [A12]，FoodKG 整合食譜、USDA 營養與本體論成為知識圖譜 [A13]。

### 2.1.4 新趨勢（2025–2026）：營養 Agent 與對話式記錄

- **Open-KNEAD（2026）**：以 Agent 將餐點拆解為食材並對應 FNDDS 代碼，份量估計比兩個前沿封閉模型好約 30% 與 53% [A10]——證明「拆解 + 資料錨定」優於端到端估計。
- **DietGlance（2025）**：以知識增強（RAG）的 AI 助理做飲食監測與個人化分析，並進行 4 週使用者研究 [A19]。
- **SnappyMeal（2025）**：多模態記錄 App，會依目標追問缺漏資訊，並進行 3 週實地部署 [A18]——與 DietSense 的 Clarification Loop 概念相近。
- **Diabot-GPT-4o（2025，臺灣）**：客製化多模態模型將臺灣飲食影像的食物辨識率從 59% 提升到 74% [A4]。

**趨勢小結**：研究正從「端到端估計」轉向「Agent 拆解 + 資料庫錨定 + 互動補資訊」。但上述系統多以英文與西式飲食為主，且很少把**安全守門**與**不確定性區間**當作一級設計目標。

## 2.2 Domain Know-how（營養領域知識）

### 2.2.1 能量平衡與能量需求估計

Hall 等人的動態模型指出，體重對攝取改變的反應很緩慢（半衰期約 1 年），靜態的「每 3,500 kcal = 1 磅」法則會高估長期減重 [D1]。個人能量需求最常用 Mifflin–St Jeor 公式估計：它由 498 名受試者推導（R² = 0.71），而 Harris–Benedict 公式平均高估約 5% [D4]。**對設計的意義**：TDEE 只能當估計基準，需要以實際體重趨勢校正。

### 2.2.2 巨量營養素與飲食品質

IOM 的 AMDR 建議成人碳水 45–65%、蛋白質 10–35%、脂肪 20–35% [D5]；國健署《每日飲食指南》以六大類食物份數作為臺灣在地的均衡標準 [D6]。「熱量數量 vs 食物品質」仍有爭論：代謝病房研究顯示等熱量下限脂短期比限碳多減少體脂，但模型預測長期差異很小 [D10]；DIETFITS（N = 609）也發現健康低脂與健康低碳的 12 個月減重無顯著差異（5.3 vs 6.0 kg）[D12]；但超加工飲食會讓人自發性多吃約 508 kcal/日 [D11]。**對設計的意義**：熱量為主指標，同時呈現營養素比例。

### 2.2.3 自我監測的成效與遵循

系統性回顧顯示自我監測與減重一致正相關 [D13]。SMARTER 試驗（N = 502、12 個月）發現每日客製化回饋並未顯著增加減重 [D14]，但追蹤分析證實遵循率在 12 個月內非線性下降，而遵循率越高越容易達到 ≥5% 減重 [D3]。**對設計的意義**：關鍵在「降低記錄成本以維持遵循」，而不只是「給更多回饋」。

### 2.2.4 自報飲食的誤差

Poslusna 等人回顧 37 篇研究，發現約 30% 受試者低報，熱量平均低估約 15% [D2]。Bajunaid 等人（2025, *Nature Food*）以 6,497 筆雙標水量測建立預測式，套用到英美全國調查後發現錯報比例超過 50% [D15]。Subar 等人則主張自報資料雖有誤差，使用得當仍有價值 [D19]。**對設計的意義**：系統應輸出區間並揭露假設，而不是假裝精確。

### 2.2.5 飲食資料庫與 App 準確度

MyFitnessPal 與比利時官方資料庫相比，熱量相關性 r = 0.96，但膽固醇、鈉的準確度差 [D16]。臺灣則有食藥署的食品營養成分資料庫可作為在地食材來源 [D18]。**對設計的意義**：以官方資料庫為主，臺式複合料理則以食材組成計算。

### 2.2.6 熱量追蹤的心理風險

大學生研究（N = 493）發現，使用熱量追蹤者有較高的飲食擔憂與限制 [D8]；105 名飲食失調患者中，74.3% 使用 MyFitnessPal，其中 73.1% 認為 App 至少「有些」加重症狀 [D9]；2026 年的系統性回顧（15 篇研究）也指出，追蹤技術在部分族群中與失序飲食相關 [D17]。**對設計的意義**：安全守門是必要功能，不是選配。

## 2.4 SWOT 評比（對應 A2Z「O」）

| 方法類別 | Strength | Weakness | Opportunity | Threat |
|---|---|---|---|---|
| 手動記錄 App | 資料庫大、使用者熟悉 | 負擔高、遵循率下降 [D3] | 結合 AI 降低負擔 | 被 AI App 取代 [S4] |
| 影像辨識 | 輸入快 | 看不到隱藏食材；MAPE 約 36% [A1] | 與文字描述互補 | 一致性低估 [S5] |
| 通用 LLM 直接問 | 口語理解強 | 幻覺、不可重現、無來源 [A2][A5] | 作為協調層 | 不安全建議 |
| LLM Agent + RAG | 可錨定資料、可拆解 [A10] | 西式為主、缺安全設計 | 在地化、加入安全與區間 | 資料庫覆蓋不足 |

## 2.5 Existing Research → Limitations → Research Gap → Our Project

```text
Existing Research                 Limitations                         Research Gap                    Our Project (DietSense)
─────────────────                 ───────────                         ────────────                    ───────────────────────
影像辨識 [A1][A14–A17]       →   看不到油/湯；MAPE≈36%          →   文字描述 + 追問尚未成熟     →   C1 繁中口語輸入
LLM 直接估計 [A2][A3][A8][A9] →   無來源、不可重現、過度自信     →   數值未與資料庫錨定          →   C4 工具計算 + 來源揭露

```

**一句話總結**：既有研究已分別證明「LLM 能理解餐點描述」「Agent 拆解 + 資料錨定比端到端更準」「自我監測需要降低負擔」「追蹤有心理風險」；但還沒有一個系統把這些整合成**以繁中口語驅動、以臺灣資料錨定、輸出不確定性區間、並內建安全守門**的 Domain AI Agent——這就是 DietSense 要填補的缺口。
